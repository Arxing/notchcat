# 決定關卡 spike：macOS 瀏海 Preview 外殼（拋棄式）

**這是拋棄式 spike，不是產品程式碼。** 目的：用同一份驗收項目比較 Tauri v2 與 GPUI 能不能做出我們要的瀏海面板行為。不寫完整功能、不寫音樂邏輯、不寫測試套件。結果是一份誠實的報告。

背景設計文件：`docs/superpowers/specs/2026-11-06-cross-platform-rust-design.md`（第 5.3、7.2 節）。現有 Swift 版殼層是行為參考：`Sources/NotchCatKit/Shell/`（NotchGeometry、NotchMode、NotchPanel、NotchHostingView、NotchShellController）與 `Sources/NotchCatKit/UI/NotchContentView.swift`。請先讀這幾個檔案了解每個行為為什麼存在（唯讀，不要修改）。

## 要做出來的東西（兩個 spike 都一樣）

一個只在 macOS 跑的小程式，畫出瀏海外殼：

1. **幾何**：找出有瀏海的內建螢幕，算出瀏海寬高與位置（與 Swift 版 `NotchDetector` 相同算法：用 `NSScreen.auxiliaryTopLeftArea`／`auxiliaryTopRightArea`，notchWidth = 螢幕寬 − 左區寬 − 右區寬，notchHeight = 左區高，centerX = 螢幕 minX + 左區寬 + notchWidth/2，頂端 = 螢幕 maxY）。沒有瀏海的機器要印出明確訊息並結束。
2. **固定大小的容器視窗**：寬 = notchWidth + 160pt，高 = 180pt，頂端對齊螢幕頂端並水平置中；視窗外框整個生命週期**不得改變**。
3. **視窗類型**：無邊框、背景透明、無陰影、不搶焦點（不成為 key／main window，點擊不啟動 App）、不出現在 Dock、所有桌面空間與全螢幕空間可見、層級高於選單列。
4. **畫出來的外型**：純黑形狀，頂端兩角直角，下方圓角；兩個狀態：Preview（寬同容器，高 = notchHeight，下圓角 10pt）與 Expanded（高 180pt，下圓角 24pt）。形狀內寫上目前狀態文字與一個 hover 進出事件計數。狀態切換用 0.28 秒 ease-in-out 動畫，**只有畫出來的形狀在動畫，視窗不動**。
5. **hover 規則（逐字照做）**：
   - 要展開：游標必須進入「目前畫出的 Preview 形狀」那個精準範圍（寬 notchWidth+160、高 notchHeight）。
   - 一旦展開，hover 範圍立刻放大成整個固定容器。
   - 游標離開範圍後**延遲 150 毫秒**才收合；期間重新進入就取消收合。
   - 收合後 hover 範圍回到 Preview 形狀。
6. **點擊穿透**：容器內「沒畫東西」的透明區域（例如收合時形狀下方的空白）必須把滑鼠點擊傳給底下的視窗；畫出來的形狀區域可以吃點擊。
7. **除錯輸出**：把每次 hover 進入／離開、狀態切換、時間戳記印到 stdout；另有一個環境變數 `SPIKE_DEBUG=1` 時把目前的 hover 範圍用紅框畫出來。
8. **重繪壓力**：開一個 250 毫秒的計時器，每次讓形狀內某個數字更新（模擬進度與歌詞每 250 毫秒重繪一次），量測閒置與計時器運作時的 CPU 使用率。

## 驗收項目（報告每一項寫 通過／失敗／無法判斷，附證據）

macOS：
- A. 無邊框、透明、不搶焦點、不進 Dock、跨空間可見。
- B. 浮在選單列之上，貼在瀏海位置（視窗 bounds 與層級的實測值）。
- C. 固定容器加手動 hover：反覆進出與游標靜止不動時**不閃爍**（以事件日誌證明：狀態切換次數符合預期，沒有抖動風暴）。
- D. 展開／收合有 0.28 秒動畫，動畫期間不誤判離開。
- E. 容器內透明區域點擊穿透。
- F. 重繪壓力下的 CPU 可接受（給出數字）。
- G. **以打包後的產物驗證 A、B、E 的透明與視窗行為**（Tauri 已知「開發模式透明正常、打包後變白底」的問題，必須用打包後的 .app 測；GPUI 則用 release 建置的執行檔）。

## 自動化驗證（允許，但要克制）

可以寫一個小腳本用 CGEvent 模擬游標移動來產生 hover 進出（走進 Preview 範圍、停住、走出範圍、快速來回、靜止抖動），讀 stdout 日誌判斷有沒有閃爍。**限制**：總共不超過約 30 秒；測試前記錄游標位置，結束後還原；不要點擊任何東西；不要輸入文字；不要動到使用者正在播放的音樂。也可用 `CGWindowListCopyWindowInfo`（例如寫一個小 Swift 或 Python 腳本）讀視窗層級與 bounds 當證據，用 `screencapture` 截圖也可以（截不到就算了，註明）。看不到螢幕的項目，明說「無法判斷」，不要假裝驗證過。

## 規則

- 所有檔案放在你自己的 spike 目錄；**不得修改 repo 內任何既有檔案**，不得 commit、不得 push、不得切換分支。
- 安裝依賴只限在你的 spike 目錄內（cargo 的全域快取不算）。不要用 sudo，不要改系統設定，不要全域安裝東西。若真的非全域安裝不可，停下來回報，不要自己裝。
- 這台機器：macOS 15.7、Apple Silicon、有瀏海的內建螢幕、Rust 1.95、Node 26 與 npm 11、Xcode 已裝（含 Metal）。
- 工作結束時不得留下任何執行中的行程。
- 時間有限：遇到卡關（編譯不過、某項行為做不到）請嘗試合理次數後如實記錄，換下一項，不要無限鑽牛角尖。**做不到也是有價值的結果**。
- 在你的 spike 目錄寫 `REPORT.md`：怎麼執行、驗收項目 A 到 G 的結果表（通過／失敗／無法判斷＋證據）、遇到的坑與解法、需要的原生（unsafe／objc）程式碼量與位置、編譯時間與產物大小、你對「用它做正式產品」的信心與主要風險、以及使用者要怎麼自己跑起來看（一條指令）。
